# Plan: The gate lints again, and it is one command

## Technical context

- **Where the config comes from.** The engine's source at `0.26.0` carried an `eslint.config.mjs` that imports `@chrisgriffin/config/eslint` and `globals`, then adds three narrow overrides: `no-unused-vars` with `ignoreRestSiblings: true` (this codebase omits a key with `const { dropped, ...rest } = obj`, so the named sibling is unused on purpose), Node and Jest globals for `__tests__/**`, and a relaxation for fixture sources, which are code the engine parses rather than code that runs. That file is the starting point, not a fresh one: it already encodes the reasons, and re-deriving them would mean rediscovering each finding.
- **Three dependencies, all public.** `eslint`, `globals`, and `@chrisgriffin/config` from `github:chrisgriffin/config#v1`. The last is a public GitHub repository installed over https, so it needs no registry token and no credential, which is FR-007: a fork's runner clones it like any public dependency. This is the one point to verify deliberately rather than assume, because `CLAUDE.md` makes "CI must need no registry auth" a standing constraint.
- **Expect findings, and expect them to be real.** `src/` has not been linted since the copy, and the suite is green, so anything ESLint raises is something no test covers. FR-002 says each is fixed in the code. A rule relaxed in config needs a reason naming what in this codebase makes it inapplicable — the three overrides above are the model for how that reads.
- **Three scripts, one chain.** `lint` is `eslint .`; `checks` is the chain `ci.yml` runs today with `lint` inserted after `prettier --check` (format, then lint, then the integrity checks, then the two generators, cheapest first as the chain already is); `verify` is `npm run checks && npm test`.
- **`verify` is the local gate, and CI deliberately does not call it.** `ci.yml`'s `checks` job calls `npm run checks`, and `test_22` keeps calling `npm test`. A `checks` job that ran `npm run verify` would run the suite a second time in the same pull request, which is FR-006 and real money: the suite takes about a minute. So `verify` exists for a person, `checks` is the shared half, and the suite stays its own job.
- **Pinning the chain so it cannot drift again.** `ci.yml`'s `checks` job must pass `run: npm run checks`. `__tests__/ci-workflow.test.js` already parses that workflow and pins the job-to-check mapping, so the assertion goes there: the `checks` job's `run:` is exactly `npm run checks`, and `package.json` has a `checks` script. That is what makes FR-005 a check rather than a hope, and it is the thing whose absence let the lint step vanish. The deliberate break (add a step to `package.json`, confirm CI would run it; change `ci.yml`'s `run:`, confirm the test fails) goes in the pull request.
- **The docs stop carrying a third and fourth copy.** `CLAUDE.md` § CI and `docs/testing.md` § Running tests each list the commands today. They point at `package.json`'s `checks` script instead and describe what the chain is for, which is also `CLAUDE.md`'s own rule about a list stated in more than one doc. `CLAUDE.md` § Coding standards gains ESLint, and the file has a hard 9500-byte budget its own `checks` job enforces, so removing the command list pays for the sentence that is added.

## Surfaces touched

- `eslint.config.mjs` — new file, from the source's own, with its three overrides and the `ignores` list FR-003 names.
- `package.json` — `eslint`, `globals` and `@chrisgriffin/config` in `devDependencies`; `lint`, `checks` and `verify` scripts. `package-lock.json` updated by the install, and the lockfile must resolve all three over https with no token.
- `src/**`, `__tests__/**`, `scripts/**` — changed only where the lint raises a finding; FR-002 governs, and the pull request lists each finding and its fix.
- `.github/workflows/ci.yml` — the `checks` job's `run:` becomes `npm run checks`. No job added, removed or renamed, so the three required check names are unchanged and no branch ruleset edit is owed.
- `__tests__/ci-workflow.test.js` — asserts the `checks` job runs `npm run checks` and that `package.json` defines it. New behaviour ships with a test, as `CLAUDE.md` § Coding standards requires.
- `CLAUDE.md` — § Coding standards says ESLint lints from the shared base; § CI points at the `checks` script instead of listing its commands; the file stays under the 9500-byte budget. This is the `claude_md_budget` the `checks` job itself enforces, so a file that grows past it fails its own gate.
- `docs/testing.md` — § The gate and § Running tests name `npm run verify` as the one local command and point at `package.json` for the chain, rather than listing it; § Running tests keeps the per-command explanations, which are the useful part.
- `.prettierignore` — confirm it needs no entry for anything added. `CLAUDE.md` says it carves out only what `docs/testing.md` lists, so a change here would owe a `docs/testing.md` change too.
- `docs/ci.md` — holds the job layout and the billed-minute reasoning. It gains the reason the `checks` job calls a script and `test_22` does not call `verify`, since that is exactly a billed-minute decision and this is where that reasoning lives.
- cost — none added, and one avoided: no job, trigger or cron is added, the lint runs inside the existing `checks` job (seconds), and FR-006 exists specifically to stop `verify` doubling the suite's minute per pull request.
- `docs/adr/` — none owed. This restores a step that was dropped by accident and collapses a list into one home, which `CLAUDE.md` already requires. If the build finds a genuine decision in it, it says so in the pull request rather than writing an ADR silently.
- `CHANGELOG.md` — nothing by hand: the release tooling writes it from conventional commits, and `CLAUDE.md` forbids hand-bumping `version`.
- none else — no reusable workflow body in [chrisgriffin/workflows](https://github.com/chrisgriffin/workflows) is touched, no required check is renamed, and the published surface does not change: `files`, `bin` and `exports` are untouched, which `scripts/ci/check-package.sh` confirms inside the chain itself.
